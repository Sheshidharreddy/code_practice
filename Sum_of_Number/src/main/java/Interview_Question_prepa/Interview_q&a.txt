6. What is the difference between ArrayList and LinkedList?
ArrayList and LinkedList both implement the List interface, but their internal data structure are different.
-	ArrayList: is backed by a dynamic array
-	LinkedList: is Implemented as doubly linked List.
Because of this ArrayList provides 0(1) random access using indexes whereas LinkedList requires O(n) traversal to reach a specific element.

- For Insertions and deletions:
-	In an ArrayList, inserting or removing elements in the middle typically required shifting elements, resulting in 0(n) complexity.
-	In an LinkedList, once the node position is know, insertion and deletion are O(1) because only links need to be update.
For Memory  perspective. LinkedList consume more memory because each node stores reference to the previous and next nodes in addition to the actual data.
In  real-world enterprise application, I generally prefer the ArrayList because most of the use case are ready- heavy, iteration is faster due to better CPU cache locality, and overall performance is usually better than LinkedList despite the theoretical insertion advantage of LinkedList


Interview Answer:
Although the LinkedList offere o(1) insertion/ deletion at a know node, in practice we often spend o(n) time locating that node first. Combined with poor cache locality and higher memory overhead. ArrayList generally outperforms LinkedList in most of the business applications. That why ArrayList is usually the default choice unless there is specific requirement that benefits from a LinkedList structure.

7. Difference between HashMap and ConcurrentHashMap?
Both HashMap and ConcurrentHashMap store data as key-value pairs, but HashMap is not thread-safe whereas ConcurrentHashMap is thread-safe.
Key Differences:
1.	Thread safety:
-	HashMap:
-	 Not thread-safe
-	Mutiple threads modifying it simultaneously can cause inconsistent data.

ConcurrentHashMap:
-	Thread-safe
-	Support concurrent read and write operations.

2.	Performance:
HashMap: Is faster in a single-threaded environment because there is no Synchronization overhead.
ConcurrentHashMap: is optimized for multi-threaded environments using fine-grained locking and CAS operations, allowing multiple thread to access the map concurrently.

8. What is HashMap’s internal working?
HashMap: internally uses an array of buckets. When a key values pair is inserted HashMap calculates the key’s hashcode .
HaspMap first obtains the key’s hashCode. It then applies a hash-spreading function by XORing the hash with its unsigned right-shifted value by 16 bits. This improves bucket distribution and minimizes collisions. After that, hashMap calculates the bucket index using (Capacity -1 ) & hash, Which is more efficient than using modulo because the capacity is always a power of two.

What is Spring transactional:
Answer:
@Transactional is a declarative transation management mechanism provided by Spring. It Create a transactional boundary around a method using AOP proxies. When the method is invoked through the spring proxy, Spring Starts a database transaction, executes the business logic and then either commits or rolls back the transaction depending on the outcome.
What actually Happens behind the scenes?
1.	Spring create a proxy around the bean.
2.	A method annotated with @Transactional is intercepted by the proxy.
3.	The Proxy obtains database connection from the transaction manager.
4.	Auto-commit is disabled
5.	All repository/JPA operations participate in the same transcation.
6.	On Successful completion -> Commit
7.	On Execptiom - > RollBack
